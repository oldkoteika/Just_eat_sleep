# План реализации Fit App Peer-to-Peer

## Обзор проекта

Мобильное приложение на Flutter для организации совместных фитнес-активностей через peer-to-peer коммуникацию. Приложение работает через интернет (WebRTC) для обмена событиями между друзьями.

**Пояснение (State Management и DI):**
- **State Management (Riverpod/Bloc)** — способ хранить и обновлять «состояние» приложения (список друзей, выбранный экран, тема и т.д.) так, чтобы несколько виджетов могли его читать и реагировать на изменения. Сейчас у вас состояние в основном в `setState()` внутри экранов — этого достаточно для простых экранов. Riverpod/Bloc нужны, когда одно и то же состояние нужно в разных местах без передачи через конструкторы или когда экранов и логики становится много.
- **Dependency Injection (get_it / riverpod)** — способ «подставлять» сервисы (хранилище, API, репозитории) в виджеты не через `new MyService()`, а через общий контейнер. Удобно для тестов (подмена моков) и когда один сервис используется во многих экранах. Пока можно обходиться без DI: создавать сервисы там, где нужно, или передавать параметром.
