# Публикация приложения в магазины

Подробная инструкция по выкладке приложения в **Google Play**, **App Store** (Apple) и **RuStore**.

---

## Общая подготовка

### Версионирование
В `pubspec.yaml` задаётся версия в формате `версия+номер_сборки`:
```yaml
version: 1.0.0+1
```
- **Версия (1.0.0)** — отображается пользователю, для всех магазинов при обновлении обычно увеличивают (например, 1.0.1).
- **Номер сборки (1)** — целое число, при каждой новой загрузке должно быть **больше** предыдущего в данном магазине.

Рекомендация: вести единую нумерацию (version + build) для всех платформ, чтобы проще отслеживать релизы.

### Материалы для карточек приложения
Заранее подготовьте:
- **Иконка:** 512×512 px (PNG/JPEG), без прозрачности по краям там, где магазин этого требует.
- **Скриншоты:** телефон (и при необходимости планшет, ТВ) в требуемых разрешениях и пропорциях (часто 16:9).
- **Краткое и полное описание** приложения на нужных языках.
- **Политика конфиденциальности** — URL страницы (обязательно для Google Play и часто для App Store/RuStore).
- **Контакт разработчика:** email (обязателен везде), по желанию сайт, соцсети.

# Часть 1. Google Play

## 1.1 Регистрация и доступ

1. Перейдите на [Google Play Console](https://play.google.com/console).
2. Войдите с Google-аккаунтом.
3. Один раз оплатите регистрационный взнос разработчика (на момент написания — $25, единоразово).
4. Заполните профиль разработчика и примите соглашения.

## 1.2 Подпись приложения (Android)

Публиковать в Google Play нужно **App Bundle (AAB)**. Файл должен быть подписан вашим ключом (upload key). Google при первой загрузке может предложить участвовать в App Signing by Google — тогда Google хранит итоговый ключ подписи, а вы подписываете только ключом загрузки.

### Создание keystore (если ещё нет)

В терминале (PowerShell или cmd) в удобной папке (не в репозитории, ключ не коммитить):

```bash
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Укажите пароли и данные владельца. Сохраните:
- путь к файлу `upload-keystore.jks`;
- пароль хранилища (store password);
- пароль ключа (key password);
- алиас (alias), например `upload`.

### Файл key.properties (локально, не коммитить)

В папке **android/** проекта создайте файл `key.properties`:

```properties
storePassword=ВАШ_ПАРОЛЬ_ХРАНИЛИЩА
keyPassword=ВАШ_ПАРОЛЬ_КЛЮЧА
keyAlias=upload
storeFile=ПУТЬ_К_upload-keystore.jks
```

`storeFile` — полный путь к `.jks` или путь относительно папки `android/`. Пример для Windows: `storeFile=C:\\keys\\upload-keystore.jks`. Файл `key.properties` не коммитить в репозиторий (в проекте уже есть правило в `android/.gitignore`).

### Подключение подписи в build.gradle.kts

В `android/app/build.gradle.kts` нужно загрузить `key.properties` и настроить `signingConfigs` для release. Пример для Kotlin DSL:

В начале файла (после `plugins { ... }`):

```kotlin
import java.util.Properties
import java.io.FileInputStream

val keystoreProperties = Properties()
val keystorePropertiesFile = rootProject.file("key.properties")
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(FileInputStream(keystorePropertiesFile))
}
```

В блоке `android { ... }` добавьте `signingConfigs` и в `buildTypes.release` укажите release-конфиг:

```kotlin
android {
    // ... namespace, compileSdk и т.д.

    signingConfigs {
        create("release") {
            keyAlias = keystoreProperties["keyAlias"] as String
            keyPassword = keystoreProperties["keyPassword"] as String
            storeFile = keystoreProperties["storeFile"]?.let { file(it) }
            storePassword = keystoreProperties["storePassword"] as String
        }
    }

    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

После этого релизные сборки будут подписываться вашим ключом.

## 1.3 Сборка AAB

В корне проекта:

```bash
flutter build appbundle
```

Готовый файл:
`build/app/outputs/bundle/release/app-release.aab`

При необходимости задать версию и номер сборки:

```bash
flutter build appbundle --build-name=1.0.0 --build-number=2
```

## 1.4 Создание приложения в Play Console

1. В Play Console: **Приложения** → **Создать приложение**.
2. Укажите название, язык по умолчанию, тип (приложение или игра), бесплатно/платно.
3. Подтвердите декларации (правила, политика конфиденциальности и т.д.).

## 1.5 Заполнение карточки и контента

- **Основные сведения:** описание, скриншоты, графика (иконка 512×512, Feature graphic и т.д.).
- **Политика конфиденциальности:** URL обязателен.
- **Категория и теги.**
- **Целевая аудитория и контент:** возрастная маркировка, опрос по контенту.
- **Реклама:** если в приложении есть реклама — укажите.
- **Данные приложения:** какие данные собираются и зачем (форма в консоли).

## 1.6 Загрузка AAB и выпуск

1. В меню приложения откройте **Релизация** → **Производство** (или тестовый трек).
2. **Создать новый выпуск** → загрузите `app-release.aab`.
3. Заполните поле **Что нового в этой версии**.
4. Сохраните и отправьте выпуск на проверку. При первом релизе нужно заполнить все обязательные разделы магазина и отправить на модерацию.

Срок проверки Google — обычно от нескольких часов до нескольких дней. После одобрения можно включить поэтапное распространение или публикацию для всех.

# Часть 2. App Store (Apple)

## 2.1 Условия

- **Mac с Xcode** — сборка под iOS делается только на macOS (см. `build_ios_macos.md`).
- **Apple Developer Program** — платная подписка ($99/год), обязательна для публикации в App Store и TestFlight (внешние тестеры).

## 2.2 Регистрация приложения в Apple

### Bundle ID
1. [Apple Developer](https://developer.apple.com/account) → **Certificates, Identifiers & Profiles** → **Identifiers**.
2. **+** → **App IDs** → **App** → Explicit App ID.
3. Укажите описание и Bundle ID (например, `com.yourcompany.fit_app_peer_to_peer`). Он должен совпадать с **Bundle Identifier** в Xcode (таргет Runner).

### Запись приложения в App Store Connect
1. [App Store Connect](https://appstoreconnect.apple.com/) → **Мои приложения** → **+** → **Новое приложение**.
2. Платформа: **iOS**. Укажите название, язык, Bundle ID (выберите зарегистрированный), SKU (уникальный код для вас).
3. Создайте приложение и заполните разделы: описание, ключевые слова, URL поддержки, URL политики конфиденциальности, категория, скриншоты, возрастной рейтинг и т.д.

## 2.3 Сборка IPA

На Mac в корне проекта:

```bash
flutter build ipa
```

IPA будет в `build/ios/ipa/`. Подробности сборки — в документе **Сборка под iPhone на MacBook** (`build_ios_macos.md`).

## 2.4 Загрузка в App Store Connect

**Вариант A — приложение Transporter (рекомендуется)**  
1. Установите [Transporter](https://apps.apple.com/app/transporter/id1450874784) из App Store на Mac.  
2. Откройте Transporter, войдите под Apple ID разработчика.  
3. Перетащите ваш `.ipa` в окно и нажмите **Доставить**.  
4. Дождитесь окончания загрузки.

**Вариант B — командная строка (API-ключ)**  
Создайте API-ключ в App Store Connect (Пользователи и доступ → Ключи) и выполните:

```bash
xcrun altool --upload-app --type ios -f build/ios/ipa/ваш_файл.ipa --apiKey KEY_ID --apiIssuer ISSUER_ID
```

**Вариант C — через Xcode**  
Откройте архив `build/ios/archive/Runner.xcarchive` в Xcode → **Distribute App** → App Store Connect → загрузка.

Через 10–30 минут сборка появится в App Store Connect в разделе **TestFlight** и в **Версия iOS** приложения.

## 2.5 TestFlight (тестирование)

1. В карточке приложения в App Store Connect откройте вкладку **TestFlight**.
2. После обработки сборки добавьте внутренних тестировщиков (учётные записи вашей команды) или создайте группу внешних тестировщиков (до 10 000 человек, первая сборка проходит проверку Apple).
3. Внешним тестировщикам приходит приглашение по email; они устанавливают приложение через приложение TestFlight на iPhone.

## 2.6 Отправка на модерацию и публикация

1. В разделе **Версия iOS** выберите или создайте версию (например, 1.0.0).
2. Укажите собранную сборку (Build), описание «Что нового», скриншоты, описание, ключевые слова, категорию, возрастной рейтинг, контакт и данные для проверки (если нужны логин/пароль).
3. **Цена и наличие** — выберите страны и цену (или бесплатно).
4. Нажмите **Отправить на проверку**. После проверки Apple (обычно 1–3 дня) приложение либо опубликуется автоматически (если выбрано), либо перейдёт в статус «Готово к продаже», и вы вручную нажмете «Выпустить».

# Часть 3. RuStore

## 3.1 Регистрация

1. Перейдите в [RuStore Консоль](https://console.rustore.ru/sign-in).
2. Зарегистрируйтесь / войдите (VK ID и т.д.).
3. Заполните данные разработчика (юридическое лицо или ИП, реквизиты). Добавить приложение может только пользователь с ролью **Владелец компании**.

## 3.2 Требования к приложению (кратко)

- Стабильная работа, заявленный функционал работает.
- Оригинальный контент, не только WebView-оболочка.
- Нет избыточной рекламы, мешающей использованию.
- Нет запрещённого контента (насилие, дискриминация, нелегальные услуги и т.д.).
- Файл подписан, имя пакета уникально; при обновлении — тот же пакет и та же подпись, номер версии выше.

Подробнее: [Требования к приложениям RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/requirement-apps).

## 3.3 Подпись и сборка для RuStore

RuStore принимает **APK** и **AAB**. Для AAB подписи добавляются до загрузки. Используйте тот же ключ (keystore), что и для Google Play, чтобы при необходимости можно было публиковать одну и ту же сборку в оба магазина.

- **AAB:** соберите так же, как для Google Play: настроенный `key.properties` и `flutter build appbundle`. Файл: `build/app/outputs/bundle/release/app-release.aab`.
- **APK:** при необходимости:
  ```bash
  flutter build apk --release
  ```
  Файл: `build/app/outputs/flutter-apk/app-release.apk`.

Требования к файлу: размер до 5 ГБ, подписан, уникальный package name (applicationId в `build.gradle.kts`).

## 3.4 Добавление приложения и загрузка версии

1. В RuStore Консоль → **Приложения** → **Загрузить версию**.
2. Если приложения ещё нет: **Добавить приложение** → введите название → **Добавить**.
3. Выберите приложение → загрузите APK или AAB. Дождитесь загрузки и обработки (не покидайте страницу во время загрузки). Обработанные файлы хранятся 14 дней; за это время нужно отправить версию на модерацию.

## 3.5 Заполнение карточки версии

- **Что нового?** — описание изменений версии.
- **Безопасность данных пользователя** — категории и типы данных, разрешения (по инструкциям RuStore).
- **Информация о приложении:** название (до 30 символов, уникальное), категория, для игр — маркировка контента.
- **Способы связи:** email обязателен, по желанию сайт, группа ВК. Минимальная версия Android подставляется из манифеста, при необходимости измените вручную.
- **Медиафайлы:**
  - Иконка: 512×512 px, PNG или JPG, до 3 МБ.
  - Скриншоты для телефона обязательны (1–10 шт.), рекомендуемое соотношение 16:9, формат PNG/JPG. При необходимости — отдельно скриншоты для планшета и ТВ.
- При необходимости: видео (через ссылку VK Видео), FAQ в карточке.

## 3.6 Модерация и публикация

- Нажмите **Отправить на модерацию**. После проверки версия получит статус «Готова к публикации».
- В настройках публикации можно включить **автоматическую публикацию** (версия появится в каталоге в течение часа после одобрения) или публиковать вручную.

Подробные шаги и ограничения: [Публикация приложений в RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication).

# Сводная таблица

| Магазин      | Формат релиза | Подпись              | Регистрация / оплата      |
|-------------|----------------|----------------------|---------------------------|
| Google Play | AAB            | Свой keystore (upload key) | $25 один раз             |
| App Store   | IPA            | Xcode / Apple (сертификаты) | $99/год (Apple Developer) |
| RuStore     | AAB или APK    | Тот же keystore, что и для Google | Бесплатно, аккаунт разработчика |

Рекомендация: для Android использовать один keystore для Google Play и RuStore; версию и номер сборки вести в `pubspec.yaml` и при сборке задавать через `--build-name` и `--build-number` при необходимости.

После первой публикации в каждом магазине обновления делаются так: увеличиваете версию/номер сборки, собираете новый AAB или IPA, загружаете в соответствующий раздел консоли и проходите модерацию по правилам магазина.
