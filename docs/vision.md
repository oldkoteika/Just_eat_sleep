# Видение приложения Fit App Peer-to-Peer

## Общее описание

Мобильное приложение на Flutter для организации совместных фитнес-активностей и событий между друзьями через peer-to-peer коммуникацию. Приложение позволяет пользователям создавать сеть друзей, обмениваться событиями и синхронизировать их с календарем устройства. Поддерживает работу как в локальной сети (Bluetooth/Wi-Fi), так и через интернет (WebRTC) для удаленных пользователей.

## Основные функции

### 1. Система друзей через QR-код

**Описание:**
Все пользователи приложения равноправны и могут быть друзьями друг друга. Пользователи могут добавлять друг друга в друзья через QR-код и обмениваться событиями.

**Предлагаемые решения:**

#### Добавление друзей через QR-код:
- **Генерация уникального QR-кода** для каждого пользователя:
  - Содержит уникальный идентификатор пользователя (UUID)
  - Может включать временную метку для безопасности
  - Возможно добавление шифрования для защиты данных
  
- **Сканирование QR-кода:**
  - Использование камеры устройства через `camera` или `mobile_scanner` пакет
  - Валидация QR-кода перед добавлением в друзья
  - Проверка на дубликаты (избежание повторного добавления)
  
- **Управление списком друзей:**
  - Локальное хранение списка друзей (SQLite/Hive)
  - Отображение статуса дружбы (онлайн/офлайн, если реализовано)
  - Возможность удаления друзей
  - Возможность массовой отправки событий нескольким друзьям одновременно

### 2. Peer-to-Peer обмен событиями

**Описание:**
Пользователи могут отправлять события (например, приглашения на тренировку) друг другу напрямую через peer-to-peer соединение. Приложение автоматически выбирает оптимальный канал связи в зависимости от доступности устройств и сети.

**Предлагаемые решения:**

#### Многоуровневая система коммуникации (рекомендуется):

**Уровень 1: Локальная сеть (приоритет для близких устройств)**
- **Bluetooth Low Energy (BLE):**
  - Работает без интернета
  - Низкое энергопотребление
  - Радиус действия: до 10-30 метров
  - Использование: обнаружение друзей поблизости, быстрый обмен при встрече
  
- **Wi-Fi Direct / Nearby Connections API:**
  - Быстрая передача данных
  - Работает без интернета
  - Больший радиус действия (до 200 метров)
  - Использование: передача больших объемов данных в локальной сети

**Уровень 2: Интернет через WebRTC (основной канал для удаленных пользователей)**
- **WebRTC (Web Real-Time Communication):**
  - Работает через интернет, не требует централизованного сервера для передачи данных
  - Поддержка NAT traversal (STUN/TURN серверы только для установления соединения)
  - Низкая задержка передачи данных
  - Шифрование на уровне протокола (DTLS/SRTP)
  - Работает на любом расстоянии при наличии интернета
  
- **Преимущества:**
  - Друзья могут обмениваться событиями из любой точки мира
  - Не требует нахождения в одной сети Wi-Fi или Bluetooth
  - Высокая скорость передачи данных
  - Надежное соединение
  
- **Архитектура WebRTC:**
  - **Signaling сервер (минимальный):** только для обмена SDP (Session Description Protocol) и ICE кандидатами
  - **STUN сервер:** для определения публичного IP адреса (может быть публичный бесплатный)
  - **TURN сервер (опционально):** для обхода сложных NAT (только при необходимости)
  - **Data Channel:** для передачи структурированных данных (события, сообщения)
  
- **Реализация:**
  - Использование `flutter_webrtc` пакета
  - Автоматическое переключение между локальными и интернет-каналами
  - Очередь сообщений для офлайн-получателей
  - Автоматическое переподключение при разрыве соединения

**Логика выбора канала:**
1. Попытка установить локальное соединение (BLE/Wi-Fi Direct) при обнаружении устройства поблизости
2. Если локальное соединение недоступно или не удалось — использование WebRTC через интернет
3. Автоматическое переключение на более быстрый канал при его появлении

#### Технические детали P2P:
- **Протокол обмена:**
  - JSON формат для событий
  - Шифрование данных (AES-256) для локальных каналов
  - WebRTC обеспечивает встроенное шифрование (DTLS)
  - Подпись сообщений для аутентификации отправителя
  
- **Структура события:**
  ```json
  {
    "id": "uuid",
    "type": "workout_invitation",
    "workout_name": "Ноги|Плечи|Грудь|Спина|Руки|Кардио|Другое",
    "date": "2026-01-27T18:00:00",
    "location": "Спортзал 'Фитнес'",
    "description": "Описание тренировки (опционально)",
    "duration": 60,
    "sender": "user_id",
    "sender_name": "Имя отправителя",
    "recipient": "user_id",
    "recipients": ["user_id1", "user_id2"],
    "status": "pending|accepted|declined",
    "reminder_time": 60,
    "added_to_calendar": false,
    "created_at": "2026-01-26T10:00:00"
  }
  ```
  
- **Наименования тренировок (предустановленный список):**
  - Ноги
  - Плечи
  - Грудь
  - Спина
  - Руки
  - Кардио
  - Другое (с возможностью указать свое наименование)

- **Типы событий:**
  - `workout_invitation` — приглашение на тренировку от друга
  - `event_update` — обновление существующего события
  - `event_cancellation` — отмена события

- **Обработка событий:**
  - Очередь отправки для офлайн-получателей
  - Автоматическая повторная попытка при неудаче
  - Уведомления о получении новых событий (push-уведомления через FCM для WebRTC)
  - Синхронизация статусов между устройствами
  - Поддержка массовой отправки нескольким друзьям одновременно
  - Возможность создания шаблонов событий для быстрого создания

### 3. Календарь событий

**Описание:**
Подтвержденные события сохраняются в календарь приложения и могут быть экспортированы в системный календарь устройства.

**Предлагаемые решения:**

#### Локальный календарь приложения:
- **Хранение данных:**
  - SQLite база данных для событий
  - Связь с таблицей друзей
  - Статусы событий: pending, accepted, declined, completed
  
- **UI компоненты:**
  - Вкладка с текущей выбранной датой в формате "12 февраля 2026 г." в верхней части экрана
  - При нажатии на дату открывается календарь для выбора даты
  - При выбранной дате отображается список тренировок (событий) на этот день
  - Детальная информация о событии при нажатии на него
  - Возможность добавления тренировки с минимальными данными (дата, время, наименование, выбор друзей)

#### Интеграция с системным календарем:
- **Android:**
  - Использование `android_calendar` или `add_2_calendar` пакетов
  - Доступ к календарю через Content Provider
  - Создание событий с напоминаниями
  
- **iOS:**
  - Использование `EventKit` через `add_2_calendar`
  - Запрос разрешений на доступ к календарю
  - Создание событий с уведомлениями

- **Функциональность:**
  - Автоматическое добавление при подтверждении (опционально)
  - Ручное добавление через кнопку "Добавить в календарь"
  - Синхронизация изменений (если событие изменено в приложении)
  - Удаление из системного календаря при отмене события

### 4. Использование функций смартфона

**Описание:**
Максимальное использование возможностей операционной системы для улучшения пользовательского опыта.

**Предлагаемые решения:**

#### Уведомления и напоминания:
- **Локальные уведомления:**
  - Напоминание о предстоящем событии (за 1 час, 30 минут, 15 минут)
  - Уведомления о новых приглашениях
  - Напоминания о неподтвержденных событиях
  
- **Реализация:**
  - `flutter_local_notifications` для локальных уведомлений
  - `timezone` для корректной работы с часовыми поясами
  - Настройка пользователем частоты напоминаний

#### Интеграция с системным календарем:
- **Напоминания через календарь:**
  - При добавлении события в системный календарь автоматически создаются напоминания
  - Настройка времени напоминания (по умолчанию за 1 час до события)
  - Возможность множественных напоминаний

#### Дополнительные функции ОС:
- **Фоновые задачи:**
  - Сканирование Bluetooth для обнаружения друзей
  - Синхронизация событий в фоне
  - Обработка входящих P2P сообщений
  
- **Доступ к датчикам:**
  - Использование акселерометра/гироскопа для фитнес-трекинга (опционально)
  - GPS для определения местоположения тренировок
  
- **Интеграция с HealthKit/Google Fit:**
  - Экспорт данных о тренировках
  - Импорт активности из системных приложений здоровья

## Структура экранов приложения

### 1. Главный экран

**Описание:**
Основной экран приложения, отображающий ключевую информацию и быстрый доступ к основным функциям.

**Элементы интерфейса:**

- **Ближайшие тренировки (3 штуки):**
  - Отображение 3 ближайших тренировок (подтвержденных и ожидающих подтверждения)
  - Для каждой тренировки:
    - Дата и время
    - Наименование тренировки (Ноги, Плечи, Грудь и т.д.)
    - Участники (друзья)
    - Кнопки действий:
      - "Подтвердить" / "Отменить" (для неподтвержденных)
      - "Добавить в календарь" (если еще не добавлено в системный календарь)
      - "Уже добавлено" (индикатор, если добавлено)

- **Кнопка "Добавить тренировку":**
  - Открывает форму создания новой тренировки
  - Редирект на экран создания события

- **Последние 3 друга:**
  - Отображение последних 3 друзей, с которыми были тренировки
  - Показывает аватар/инициалы и имя друга
  - При нажатии можно перейти к деталям друга или истории тренировок

- **Кнопка "Добавить друга":**
  - Редирект на страницу сканирования QR-кода
  - Быстрый доступ к функции добавления друзей

### 2. Экран календаря

**Описание:**
Экран для просмотра тренировок по датам и создания новых тренировок.

**Элементы интерфейса:**

- **Верхняя часть:**
  - Вкладка с текущей выбранной датой в формате "12 февраля 2026 г."
  - При нажатии на дату открывается календарь для выбора даты

- **Календарь:**
  - Отображение календаря с отметками дней, в которые есть тренировки
  - Выбор даты для просмотра тренировок

- **Список тренировок:**
  - При выбранной дате отображается список всех тренировок на этот день
  - Для каждой тренировки: время, наименование, участники
  - При нажатии на тренировку открывается детальная информация

- **Создание тренировки (минимальная форма):**
  - **Дата и время:** выбор из календаря и времени (по умолчанию выбраная дата)
  - **Наименование:** выбор из предустановленного списка:
    - Ноги
    - Плечи
    - Грудь
    - Спина
    - Руки
    - Кардио
    - Другое (с возможностью ввода своего)
  - **Выбор друзей:** мультиселект из списка друзей для приглашения
  - **Уведомление:** настройка времени напоминания (по умолчанию за 1 час до тренировки)
  - Кнопка "Создать тренировку" для отправки приглашений

### 3. Экран "Мои друзья"

**Описание:**
Экран для управления списком друзей.

**Элементы интерфейса:**

- **Список друзей:**
  - Отображение всех добавленных друзей
  - Для каждого друга:
    - Имя (ФИО, если указано)
    - Аватар или инициалы (аватар можно добавить из галереи или сфотографировать)
    - Статус (онлайн/офлайн, если реализовано)
    - Количество совместных тренировок (опционально)

- **Действия с друзьями:**
  - Просмотр профиля друга (при нажатии на карточку)
  - Удаление друга (кнопка удаления или свайп)
  - Отправка приглашения на тренировку (быстрое действие)

- **Добавление друга:**
  - Кнопка "Добавить друга" в нижней части "+" 
  - Два способа добавления:
    1. **Сканирование QR-кода:**
       - Открытие камеры для сканирования QR-кода друга
       - Автоматическое добавление при успешном сканировании
    2. **Распознавание из галереи:**
       - Выбор изображения из галереи устройства
       - Распознавание QR-кода на изображении
       - Добавление друга при успешном распознавании

### 4. Экран "Профиль"

**Описание:**
Экран с информацией о текущем пользователе и его QR-кодом для добавления в друзья.

**Элементы интерфейса:**

- **Информация о пользователе:**
  - **ФИО:** отображение и возможность редактирования
  - Поле для ввода/редактирования имени пользователя
  - Сохранение изменений

- **QR-код:**
  - Отображение уникального QR-кода пользователя
  - QR-код содержит UUID пользователя для идентификации
  - Возможность поделиться QR-кодом (сохранение в галерею, отправка)
  - Обновление QR-кода (если требуется обновление идентификатора)

- **Настройки:**
  - **Уведомления:** переключатель ВКЛ/ВЫКЛ для включения/отключения уведомлений о тренировках и приглашениях
  
- **О приложении:**
  - Описание приложения
  - Информация о том, что все данные хранятся локально на устройстве
  - Подтверждение приватности: данные не передаются на внешние серверы (кроме минимального signaling сервера для WebRTC, который не хранит пользовательские данные)
  - Версия приложения

## Архитектурные решения

### Рекомендуемый стек технологий:

1. **State Management:**
   - Riverpod или Bloc для управления состоянием
   - Локальное хранилище: Hive или SQLite (через `drift`)

2. **P2P Коммуникация:**
   - **WebRTC (основной канал):**
     - `flutter_webrtc` для WebRTC соединений через интернет
     - STUN/TURN серверы для NAT traversal (можно использовать публичные или собственные)
     - Signaling сервер (минимальный, только для обмена SDP) — может быть реализован на Firebase Realtime Database или WebSocket сервере
   - **Локальные каналы:**
     - `flutter_blue_plus` для Bluetooth Low Energy
     - `nearby_connections` (Android) / `multipeer_connectivity` (iOS) для Wi-Fi Direct
   - **Шифрование и безопасность:**
     - `crypto` для шифрования локальных сообщений
     - WebRTC обеспечивает встроенное шифрование (DTLS/SRTP)
   - **Push-уведомления:**
     - `firebase_messaging` для уведомлений о входящих событиях через WebRTC

3. **QR-код:**
   - `mobile_scanner` или `qr_code_scanner` для сканирования
   - `qr_flutter` для генерации QR-кодов

4. **Календарь:**
   - `table_calendar` для UI календаря
   - `add_2_calendar` для интеграции с системным календарем
   - `flutter_local_notifications` для уведомлений

5. **Дополнительно:**
   - `permission_handler` для запроса разрешений
   - `geolocator` для определения местоположения
   - `timezone` для работы с часовыми поясами

## Безопасность

- **Шифрование коммуникации:**
  - WebRTC: встроенное шифрование на уровне протокола (DTLS/SRTP)
  - Локальные каналы: AES-256 шифрование сообщений
  - Подпись сообщений для аутентификации отправителя
  
- **Аутентификация:**
  - Проверка подлинности друзей через QR-код
  - Проверка прав доступа перед отправкой событий (только друзьям)
  
- **Хранение данных:**
  - Локальное хранение данных (без централизованного сервера для пользовательских данных)
  - Минимальный signaling сервер только для установления WebRTC соединений (не хранит данные)
  - Защита персональных данных пользователей
  - Опциональное шифрование локальной базы данных

## Архитектура WebRTC

### Компоненты системы:

1. **Signaling сервер (минимальный):**
   - Назначение: обмен SDP (Session Description Protocol) и ICE кандидатами между пирами
   - Реализация: Firebase Realtime Database, WebSocket сервер, или простой HTTP сервер
   - Хранение: только временные данные для установления соединения (удаляются после установления)
   - Альтернатива: можно использовать существующие публичные signaling серверы

2. **STUN сервер:**
   - Назначение: определение публичного IP адреса устройства
   - Варианты: публичные бесплатные серверы (Google STUN, Twilio) или собственный
   - Пример: `stun:stun.l.google.com:19302`

3. **TURN сервер (опционально):**
   - Назначение: ретрансляция трафика для обхода сложных NAT/Firewall
   - Используется только когда прямое P2P соединение невозможно
   - Варианты: Twilio, собственный сервер (coturn), или облачные решения

### Процесс установления соединения:

1. Пользователь A хочет отправить событие пользователю B
2. Приложение проверяет доступность локальных каналов (BLE/Wi-Fi)
3. Если локальные каналы недоступны:
   - A и B подключаются к signaling серверу
   - A создает WebRTC offer и отправляет через signaling сервер
   - B получает offer, создает answer и отправляет обратно
   - Оба обмениваются ICE кандидатами через signaling сервер
   - Устанавливается прямое P2P соединение через WebRTC Data Channel
   - Signaling сервер больше не используется для передачи данных

### Преимущества WebRTC подхода:

- **Децентрализация:** данные передаются напрямую между устройствами
- **Безопасность:** встроенное шифрование на уровне протокола
- **Масштабируемость:** не требует мощного сервера для передачи данных
- **Надежность:** автоматическое переподключение и обработка ошибок
- **Универсальность:** работает на любом расстоянии при наличии интернета
